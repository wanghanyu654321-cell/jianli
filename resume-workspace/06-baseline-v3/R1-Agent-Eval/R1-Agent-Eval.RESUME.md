### 企业客服 Agent｜Agent Builder 项目实践

- **问题定义与 Eval Scope：** 围绕企业客服 Agent 负责问题定义、架构边界、验收标准和评测设计，明确需要验证的任务范围、系统边界以及什么情况可以认为当前方案达到阶段要求。
- **方案边界：** 负责架构边界和方案取舍，项目材料覆盖权限边界、Runtime 预算、工具调用、检索、Evidence Governance 和 Routing 规则；这些约束用于限定 Agent 在权限、证据或候选不足时的行为范围。
- **Case Design：** 针对检索候选、证据准入、工具调用及安全/权限设计测试场景，覆盖**无候选、单候选、多候选歧义**等不同情况，用不同 Case 检查 Agent 在正常和失败场景下的行为是否符合预期。
- **Badcase / Acceptance：** 负责 Badcase 归因、测试验收和项目状态判断，把失败 Case 作为评估方案是否达到当前阶段要求的重要依据，而不是只看一次回答是否成功。
- **Regression：** 沉淀 **40 个 Frozen Cases** 作为固定回归基线，并设置 Holdout 验证，用于检查后续调整是否破坏既有行为以及在固定 Case 之外是否仍保持表现。
- **测试结果：** 项目材料记录 Safety 30/30、Robustness 100/100、Holdout 60/60、Governed Knowledge 46/46、Public Top1 96%、Recall@3 100%、Routed Outcome 100% 等现有测试集结果；这些数字只代表当前测试集表现，不表述为生产流量结果。
- **实现方式：** 通过 AI Coding Agent 协作完成实现与 Review，本人负责问题定义、方案取舍、验收设计、测试和状态判断；项目保持 **DOCUMENTED_ONLY / REPO_NOT_VERIFIED**，不表述为独立手写全部代码或生产上线。
