## 工作经历

### 杭州人瑞网络科技有限公司｜评测专家（淘天 Data Agent）｜2025.09–2026.06

- **Data Agent 评测：** 参与 Query、Data Agent 输出、召回结果和商品相关性评测，将用户意图、商品语义及业务规则落到具体 Case 判断；同时接触多轮上下文、工具调用结果、执行步骤完整性及最终回答是否解决用户问题等 Agent 行为评测。
- **开放题 / Path Eval：** 面对没有唯一标准答案的问题，结合既有指标选取高分 / 低分答案，对比不同 Layer / Path，观察意图、工具选择、工具结果和异常处理等关键节点，再将稳定差异沉淀为判断规则。
- **规则治理：** 新任务进入执行前，先结合实际 Case 检查定义、业务上下文、判断边界和场景覆盖，再转化为下游可执行的判断口径、示例和培训内容；规则补充同时控制复杂度，避免引入新的理解成本和歧义。
- **Bad Case / 根因分析：** 对重复偏差结合 Case、人员理解方式与规则本身判断问题来自业务知识、上下文、规则表达、判断边界还是执行流程，再分别补充背景、收窄边界、增加示例或调整执行方式。
- **QA / 质量复核：** 常规承担约 **10% 抽检**及质量复核，单项任务下游 BPO **10+ 人**；累计参与沉淀 **10+ 份 SOP / 规则 / 执行文档**，部分任务一致性约 **80%→95%**，复杂任务约 **60%→85%**。
- **版本效果 / A/B：** 参与执行层灰度桶 / A/B 测试及相关取数，结合 **DAU、CTR、转化、业务水位**观察版本变化和异常情况，并整理反馈。
- **搜索 Query 理解：** 接触 Query 预处理 / 理解 / Rewrite、召回、Filter、排序、SERP 与反馈链路，并使用 L1/L2/L3 相关性分级参与判断。

## 项目经历

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**项目背景：** 面向本地生活门店微信接待场景，解决重复咨询响应不及时、预约 / 线索意向容易丢失、异常问题缺乏稳定转人工流程等问题。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL 16 / pgvector｜Docker Compose｜RAG / 知识库｜Prompt / 指令｜Tool Use｜Agent Runtime｜Eval / Regression / Harness｜CI

- **评测集设计：** 将质量判断从最终答案扩展到知识依据、路由、Tool Use、无答案 / 歧义和权限行为；以 **40-case 冻结主测试集**覆盖可回答、无答案和歧义场景，并保留 **60-case Blind Holdout** 等分层验证。
- **边界测试：** 加入租户 / 门店隔离、未批准知识、失效 / 退役版本等 Negative Cases；即使检索成功，只要范围、状态、版本或歧义条件不成立，仍要求拒答或转人工。
- **Bad Case / 根因分析：** 评测失败后先判断知识、权限、工具、业务动作和流程是否正常，只有底层链路成立而模型行为仍偏差时，才优先调整 Prompt / 指令。
- **版本回归 / Holdout：** 修复目标 Bad Case 后重新跑冻结测试集与 Blind Holdout，同时检查正常回答、无答案、歧义、权限和 Safety 行为是否退化。
- **Tool Use：** Ticket / 人工接管等工具调用按 **权限通过 → 状态写入 → 持久化 → scoped read-back → 验收** 判断，不把“模型说完成”或单次 Tool Call 当作业务成功。
- **执行轨迹分析：** 通过结构化 Trace 观察意图、规划 / 决策节点、工具选择、工具结果和错误处理，并记录首 Token 延迟、工具调用数量等运行指标，用于定位多步骤执行异常。
- **自动化回归 / CI：** 通过 Eval Harness 管理 Case、Config、Runtime、Evaluator 与 Report；回归评测接入 CI，缺失 / 重复 Case、配置不匹配或运行中断时不进入版本通过判断，并由 Safety、Knowledge、Retrieval、Runtime 等独立 Quality Gate 保留结果。

**项目状态：** 已完成微信部署与实体本地生活门店 POC，门店开始在接待场景中使用；现场 Case 正逐步回流到 Dataset 与 Regression Set。
