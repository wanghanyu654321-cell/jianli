# R4｜AI 产品运营 / 智能服务产品运营

## 求职方向

**AI 产品运营 / 智能服务产品运营 / AI Product Ops**

## 个人总结

具备从用户反馈、业务数据和实际场景中发现问题，进一步做需求拆解、优先级判断、方案推进和结果验证的经历。经历覆盖电商经营、淘天搜推侧 Data Agent 评测和 Agent 项目，能够同时从用户、业务、质量和工程约束理解产品问题。

在朗臻从牙膏品类电商运营逐步承担项目运营管理，负责约 **5 个跨平台店铺**，年度整体 GMV 约 **1,500 万**；在今宜参与抖音新盘 0→1，通过内容 / 直播验证、千川投流和团队协同推动同一账号月 GMV 从早期约 **7 万提升至接手首月约 43 万**。两段经历持续训练了从问题发现、用户 / 数据验证到跨团队落地的能力。

个人数字前台 Agent 将这些能力迁移到 AI 产品场景：从门店微信线上接待问题出发，明确目标用户、核心场景、第一阶段范围、验收标准和后续迭代逻辑；项目已完成微信部署与实体本地生活门店 POC，并开始在接待场景中使用，产品输入开始来自真实咨询、预约 / 线索、人工接管和一线反馈。

## 工作经历

### 杭州人瑞网络科技有限公司｜评测专家（淘天搜推侧 Data Agent）｜2025.09–2026.06

- **问题发现：** 参与 Query、Data Agent 输出、召回和相关性评测，同时承担规则理解、QA 和复杂 Bad Case，持续发现影响质量的业务上下文、规则边界和执行理解问题。
- **需求澄清：** 新任务执行前结合实际 Case 检查定义、业务上下文和场景覆盖；对无法稳定执行的部分集中反馈并完成必要确认。
- **规则 / 流程优化：** 对重复 Bad Case 区分知识背景、规则表达、判断边界和业务流程问题，再决定补背景、改说明、增加示例还是收窄判断空间。
- **用户 / 执行反馈：** 通过培训、日常沟通和 QA 了解执行人员真实卡点，并将问题转化为业务背景、案例、规则或流程调整。
- **验证闭环：** 常规承担约 **10% 抽检**，累计参与沉淀 **10+ 份 SOP / 规则 / 执行文档**；部分任务一致性约 **80%→95%**、复杂任务约 **60%→85%**。
- **版本反馈：** 参与灰度 / A/B 及 DAU、CTR、转化、业务水位等指标观察，将执行反馈和数据变化共同作为版本判断输入。

### 杭州今宜商贸有限公司｜抖音项目代运营｜2024.11–2025.07

- **用户 / 产品表达：** 围绕目标用户、核心卖点和使用场景重新组织商品表达，不直接把单一市场信号当结论。
- **内容验证：** 通过短视频测试卖点、视觉和使用场景，再将表现更有效的方向迁移到直播，并参与双机位方案设计。
- **数据诊断：** 本人直接承担巨量千川投流，根据 CTR、CVR、ROI、素材和直播承接判断问题位于内容、流量还是转化层，再决定下一步优化对象。
- **0→1 项目推进：** 协同约 **6 人直播团队**推进内容、主播、排期、投流和复盘；同一新盘账号月 GMV 从早期约 **7 万提升至接手首月约 43 万**。
- **经营反馈：** 持续结合流量、营销和交易数据判断产品表达、内容和经营结果之间的关系，而不是只看内容产出数量。

### 浙江朗臻网络科技有限公司｜电商运营 → 宠物项目运营管理｜2022.03–2024.07

- **项目运营管理：** 从牙膏品类电商运营逐步承担项目管理，负责约 **5 个跨平台店铺**的 GMV、利润率、DSR 和渠道结果，年度整体 GMV 约 **1,500 万**。
- **用户 / 市场需求：** 新商品启动前结合市场规模、搜索需求、关键词增长和竞争环境判断机会；消费者反馈用于发现潜在需求，并与更大范围市场 / 搜索数据交叉使用。
- **需求落地：** 老客户持续出现的猫粮需求成为产品线扩展输入；老板确定大方向后，本人基于市场、搜索、消费者反馈和经营信息落细具体产品要求，并与工厂 / 产品开发侧推进。
- **搜索 / 产品反馈：** 通过 Query、关键词、标题和详情属性持续优化商品与需求匹配，推动核心商品搜索排名由百名外进入 **细分类目前 10**。
- **经营问题诊断：** 商品表现不达预期时，结合流量、点击、转化、商品和链接状态判断问题，再决定优化表达、调整商品还是测试新的方向；另一核心 SKU 接手首月内日 GMV约 **1,000+→15,000+**。
- **项目推进：** 协同内容、客服、供应链、品牌、平台和工厂推进商品、活动、供应和渠道事项，并做优先级、排期和阶段检查。

## 项目经历

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**项目背景：** 聚焦实体门店微信等私域入口的线上第一接待，解决重复咨询、预约 / 线索承接和异常转人工问题。

- **问题定义：** 从“有私域流量但线上接待不稳定”出发，明确一线店员 / 客服和管理侧的核心场景，而不是从“做一个 Agent”反推需求。
- **产品范围：** 第一阶段不做完整 CRM，也不做全自动客服；优先保留知识问答、预约 / 线索、轻量业务状态和人工接管。
- **MVP / 优先级：** 按场景频率、业务价值、风险和可验收性排序功能，知识库、预约意向、Ticket / 人工接管和权限控制优先进入主流程。
- **需求拆解：** 将目标用户、用户旅程、产品范围、业务流程和验收标准组织成可实现的需求结构，并通过真实 Case 持续反查实现是否符合业务预期。
- **Bad Case 迭代：** 出现问题时先区分需求定义、知识库 / RAG、Prompt、业务流程、权限还是业务状态，再回到对应层修改。
- **方案取舍：** Semantic Selector 历史测试约 **P50 7.35s、P95 16.67s**，不符合当前同步运行预算，因此未进入主路径；技术方案以用户价值、质量和运行成本共同成立为前提。
- **微信部署 / 门店 POC：** 已完成微信部署与实体本地生活门店 POC，门店开始在接待场景中使用；真实咨询、人工接管和一线反馈逐步成为后续需求与迭代输入。
