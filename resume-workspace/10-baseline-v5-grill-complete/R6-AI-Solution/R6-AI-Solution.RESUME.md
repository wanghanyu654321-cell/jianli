## 工作经历

### 杭州人瑞网络科技有限公司｜评测专家（淘天 Data Agent）｜2025.09–2026.06

- **业务需求理解：** 承接上游业务规则和任务要求后，先理解业务目标、数据口径和判断边界，再转化为下游 BPO 可执行的标准和培训内容。
- **需求澄清：** 执行前主动发现定义不清、业务上下文不足或场景覆盖缺口，并集中与上级确认；执行中持续同步阶段、问题和待确认事项。
- **问题解释 / 反馈：** 对重复 Bad Case 结合执行理解、规则和业务上下文判断问题来源，再推动规则、示例、培训或执行边界调整。
- **质量结果：** 单项任务下游 **10+ 人**；累计参与沉淀 **10+ 份 SOP / 规则 / 执行文档**，部分任务一致性约 **80%→95%**、复杂任务约 **60%→85%**。
- **版本反馈：** 参与灰度 / A/B 及 DAU、CTR、转化、业务水位等指标观察，并汇总异常及版本反馈。

### 杭州今宜商贸有限公司｜抖音项目代运营｜2024.11–2025.07

- **业务目标：** 与老板确认当前更偏 GMV、ROI、利润还是新盘增长，再据此决定投流、内容、达人合作和资源投入。
- **方案取舍：** 新盘早期先改善内容和直播承接，再逐步放大付费流量，避免用更多预算覆盖基础问题。
- **达人 BD：** 新链接缺少销量、权重和成熟素材时，直接通过微信 / 电话推进达人合作，并根据内容匹配、历史销售和合作意愿判断优先级。
- **商业条件：** 冷启动阶段在基础成本风险可覆盖前提下，可以适当让渡达人渠道短期利润换取首批销量、商品权重和起盘速度。
- **项目结果：** 达人合作单月销售额合计 **10 万元+**；同一新盘账号月 GMV 从早期约 **7 万提升至接手首月约 43 万**。
- **项目推进：** 协同约 **6 人直播团队**在业务目标、资源条件和数据结果之间持续推进策略与执行。

## 项目经历

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**业务问题：** 门店已有微信私域流量，但重复咨询、预约 / 线索和异常问题高度依赖人工即时处理，需要稳定的线上第一接待和人工接管机制。

- **需求分析：** 将第一阶段核心能力收敛为知识问答、预约 / 服务意向、Ticket / 人工接管、权限控制和真实业务状态，不把复杂多 Agent 或营销自动化作为 POC 前置条件。
- **方案设计：** 将渠道 / 身份适配、Agent 运行时、RAG / 知识库、权限控制和业务接口拆分，便于后续接不同渠道或业务系统时保持核心逻辑稳定。
- **业务 / 技术翻译：** 将知识治理解释为“回答是否来自当前门店可使用的信息”，将权限控制解释为“Agent 能理解用户意图，不代表它有权直接执行”，让技术边界转化为业务可理解的自动化边界。
- **风险识别：** 提前处理租户 / 门店隔离、业务状态一致性、工具调用成功但业务动作未落库等问题，避免这些问题在 POC 中以业务异常形式暴露。
- **POC 验收：** 正常回答、无答案 / 歧义、权限、业务动作、人工接管和系统集成分别验收，不用单一准确率代表整体方案质量。
- **POC 交付：** 已完成微信部署与实体本地生活门店 POC，门店开始在接待场景中使用；现场问题和反馈继续进入后续方案优化。
- **技术沟通：** 能围绕 Prompt、RAG、API、数据库、Tool Use、权限、Agent Runtime 和评测讨论具体实现，同时把技术限制重新翻译成业务方可以理解的方案边界。
