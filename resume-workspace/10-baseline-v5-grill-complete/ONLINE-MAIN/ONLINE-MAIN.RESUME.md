## AI 项目实践

### 数字前台 Agent｜需求分析 → 方案设计 → 微信部署 → 门店 POC

**项目背景：** 面向小型门店 / 服务型商家的线上第一接待和私域承接。针对微信等私域入口中重复咨询响应不及时、预约 / 线索意向容易丢失、异常问题缺乏稳定转人工流程等问题，第一阶段聚焦：

**私域入口 → 第一接待 → 知识问答 → 预约 / 线索意向 → 轻量业务状态 → 人工接管 → 后续跟进。**

**本人负责：** 问题定义、方案边界、验收标准、评测设计、Bad Case 归因、方案取舍、测试验收和项目状态判断；通过 AI Coding Agent 协作完成实现与 Review。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL 16 / pgvector｜Docker Compose｜Agent｜RAG / 知识库｜Prompt / 指令｜工具调用｜评测 / 回归

- **需求分析：** 第一阶段不重建完整 CRM，也不扩展为全能数字员工，优先解决常见咨询、预约 / 线索、异常转人工等高频问题，并根据真实使用反馈逐步扩展能力。
- **RAG / 知识问答：** 检索结果先作为候选知识，再结合门店范围、知识状态、版本和歧义情况决定回答、拒答或转人工，避免“检索到内容”直接等同于“可以回答”。
- **权限控制：** Agent 可以识别意图并提出动作，但身份、门店范围、权限和最终写操作由服务端控制；Ticket / 人工接管等动作需完成权限检查、状态写入、持久化和按权限范围回读后才视为成功。
- **回归测试：** 建立 **40 个冻结测试案例（24 个可回答 / 8 个无答案 / 8 个歧义）**，并加入跨租户 / 门店、未批准知识、失效版本等负向测试；问题修复后执行回归测试，检查正常回答、无答案、歧义和权限边界是否出现退化。
- **POC 交付：** 已完成**微信部署与实体本地生活门店 POC**，门店开始在接待场景中使用；项目从内部工程验证进入门店流程验证，并开始积累咨询、异常、人工接管和一线反馈。
- **项目状态：** 已完成微信部署、门店 POC 并开始实际使用；长期稳定性、规模化复制、持续付费、业务 ROI、生产环境 SLA 及大流量能力仍需持续验证。
