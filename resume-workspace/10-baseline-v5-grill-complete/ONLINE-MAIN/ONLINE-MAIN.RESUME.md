## 工作经历

### 杭州人瑞网络科技有限公司｜评测专家（淘天搜推侧 Data Agent）｜2025.09–2026.06

- **搜推侧 Data Agent 评测：** 参与 Query、Agent 输出、召回结果和商品相关性评测，将用户意图、商品语义和业务规则落实到具体 Case 判断；同时接触多轮上下文、工具调用结果、执行步骤完整性及最终回答是否解决用户问题等 Agent 行为评测。
- **搜索 Query 理解：** 接触 Query 预处理 / 理解 / Rewrite、召回、Filter、排序、SERP 与反馈链路，并使用 L1/L2/L3 相关性分级参与判断。
- **版本效果 / A/B：** 参与执行层灰度桶 / A/B 测试及相关取数，结合 **DAU、CTR、转化、业务水位**观察版本变化和异常情况，并整理反馈。
- **QA / 质量复核：** 常规承担约 **10% 抽检**，单项任务下游 BPO **10+ 人**；累计参与沉淀 **10+ 份 SOP / 规则 / 执行文档**，部分任务一致性约 **80%→95%**、复杂任务约 **60%→85%**。
- **开放题 / Path Eval：** 面对没有唯一标准答案的问题，结合既有指标对比高分 / 低分答案及不同处理路径，观察意图、工具选择、工具结果和异常处理等关键节点差异，再将稳定差异沉淀为后续可执行的判断规则。
- **规则治理：** 新任务进入执行前先结合实际 Case 检查定义、业务上下文、判断边界和场景覆盖，再完成必要对齐，并整理为下游 BPO 可执行的判断标准、案例和培训内容。
- **Bad Case / 根因分析：** 对重复偏差区分业务知识、上下文、规则表达、判断边界和执行流程等原因，再通过补充背景、收敛规则、增加案例或调整执行方式进行改善，并在后续复测 / 抽检中验证效果。

## AI 项目实践

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**项目背景：** 面向小型门店 / 服务型商家的线上第一接待和私域承接，解决重复咨询响应不及时、预约 / 线索意向容易丢失、异常问题缺乏稳定转人工流程等问题。

**本人负责：** 问题定义、需求拆解、方案边界、验收标准、评测设计、Bad Case 归因、方案取舍、测试验收和项目状态判断；通过 AI Coding Agent 协作完成实现与 Review。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL 16 / pgvector｜Docker Compose｜Agent｜RAG / 知识库｜Prompt / 指令｜Tool Use｜Eval / Regression / CI

- **微信部署 / 门店 POC：** 已完成**微信部署与实体本地生活门店 POC**，门店开始在接待场景中使用；现场咨询、异常、人工接管和一线反馈逐步回流到后续评测与版本迭代。
- **需求拆解：** 第一阶段不重建完整 CRM，也不扩展为全能数字员工，优先解决常见咨询、预约 / 线索、异常转人工等高频问题，并根据场景约束确定 Agent、知识库、权限和人工接管边界。
- **Agent 评测 / 回归测试：** 将质量判断从最终回答扩展到知识依据、无答案 / 歧义、Tool Use、权限、业务状态和执行轨迹；建立冻结测试集、Blind Holdout 与版本回归机制，并通过 Eval Harness / CI / Quality Gate 检查修改后回答、路由、权限和状态行为是否退化。
- **RAG / 知识问答：** 检索结果先作为候选知识，再结合门店范围、知识状态、版本和歧义情况决定回答、拒答或转人工，避免“检索到内容”直接等同于“可以回答”。
- **Tool Use / 权限控制：** Agent 可以识别意图并提出动作，但身份、门店范围、权限和最终写操作由服务端控制；Ticket / 人工接管等动作需完成权限检查、状态写入、持久化和按权限范围回读后才视为成功。
