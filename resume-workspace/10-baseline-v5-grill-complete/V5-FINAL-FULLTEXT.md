- **项目运营管理：** 后续负责约 **5 个跨平台店铺**的 GMV、利润率、DSR、月 / 季目标和渠道结果，年度整体 GMV 约 **1,500 万**。
- **跨团队协调：** 协同内容、客服、供应链、品牌、京东小二及工厂 / 产品开发等多方推进经营事项，并参与大促备货、供应排期和库存周转。

## 项目经历

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**业务问题：** 门店已有微信私域流量，但重复咨询、预约 / 线索和异常问题高度依赖人工即时处理，需要稳定的线上第一接待和人工接管机制。

- **需求分析：** 将第一阶段核心能力收敛为知识问答、预约 / 服务意向、Ticket / 人工接管、权限控制和真实业务状态，不把复杂多 Agent 或营销自动化作为 POC 前置条件。
- **方案设计：** 将渠道 / 身份适配、Agent 运行时、RAG / 知识库、权限控制和业务接口拆分，便于后续接不同渠道或业务系统时保持核心逻辑稳定。
- **业务 / 技术翻译：** 将知识治理解释为“回答是否来自当前门店可使用的信息”，将权限控制解释为“Agent 能理解用户意图，不代表它有权直接执行”，让技术边界转化为业务可理解的自动化边界。
- **风险识别：** 提前处理租户 / 门店隔离、业务状态一致性、工具调用成功但业务动作未落库等问题，避免这些问题在 POC 中以业务异常形式暴露。
- **POC 验收：** 正常回答、无答案 / 歧义、权限、业务动作、人工接管和系统集成分别验收，不用单一准确率代表整体方案质量。
- **POC 交付：** 已完成微信部署与实体本地生活门店 POC，门店开始在接待场景中使用；现场问题和反馈继续进入后续方案优化。
- **技术沟通：** 能围绕 Prompt、RAG、API、数据库、Tool Use、权限、Agent Runtime 和评测讨论具体实现，同时把技术限制重新翻译成业务方可以理解的方案边界。
