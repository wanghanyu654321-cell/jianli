### 杭州人瑞网络科技有限公司｜评测专家（淘天 Data Agent）｜2025.09–2026.06

- **Data Agent 评测：** 参与 Data Agent 输出、任务结果和相关 Case 的质量评测，将用户需求、业务规则和判断要求落实到具体执行标准；同时接触多轮上下文、工具调用结果、执行步骤完整性及最终回答是否解决用户问题等 Agent 行为评测。

- **需求分析 / 澄清：** 承接上游业务文档、数据口径及任务要求后，先结合实际 Case 理解规则适用范围、业务上下文和执行难点；新任务放量前主动识别定义不清、场景覆盖不足、上下文缺失或判断空间过宽等问题，并集中反馈确认，减少问题进入大规模执行后的返工。

- **规则转译 / SOP：** 将上游相对抽象的业务要求转化为 BPO 可直接执行的判断标准、案例和培训内容；累计参与沉淀 **10+ 份 SOP / 规则 / 执行文档**，在保证判断边界清晰的同时控制规则复杂度和理解成本。

- **QA / 项目推进：** 常规承担约 **10% 抽检**及质量复核，单项任务下游 BPO **10+ 人**；在上级与执行团队之间持续同步进展、问题和待确认事项，部分任务一致性约 **80%→95%**、复杂任务约 **60%→85%**。

- **Bad Case / 问题定位：** 对重复偏差结合具体 Case 判断问题来自业务知识、上下文、规则表达、判断边界还是执行流程，再分别通过补充背景、收敛规则、增加案例、培训或调整执行方式处理，并在后续抽检 / 复测中继续验证。

- **版本效果 / A/B：** 参与执行层灰度桶 / A/B 测试及相关取数，结合 **DAU、CTR、转化、业务水位**观察版本变化和异常情况，将线上数据与 Case 质量结合整理反馈，支持版本问题定位与后续迭代。

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**项目背景：** 面向小型门店 / 服务型商家的线上第一接待和私域承接，针对重复咨询响应不及时、预约 / 服务意向容易丢失、异常问题缺乏稳定人工接管流程等问题设计数字前台 Agent。

**本人负责：** 问题定义、需求拆解、方案边界、优先级判断、验收标准、评测设计、Bad Case 归因、方案取舍、测试验收和项目状态判断；通过 AI Coding Agent 协作完成实现与 Review。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL 16 / pgvector｜Docker Compose｜Agent｜RAG / 知识库｜Prompt / 指令｜Tool Use｜Eval / Regression / CI

- **POC 交付：** 已完成**微信部署与实体本地生活门店 POC**，门店开始在接待场景中使用，项目从内部方案与工程验证进入门店流程验证；现场咨询、异常问题、人工接管和一线反馈逐步回流后续评测与版本迭代。

- **需求分析：** 从门店线上第一接待流程出发，第一阶段优先解决常见咨询、预约 / 服务意向、线索承接和异常转人工等高频问题；不重建完整 CRM，也不扩展为全能数字员工，根据实际场景价值、风险和实施复杂度确定首版范围。

- **方案设计：** 将整体接待流程拆成知识问答、轻量业务状态、权限控制、Ticket / 人工接管等模块，使 Agent 负责意图理解和任务决策，同时将身份、权限、业务状态及最终写操作保留在确定性的服务端链路中。

- **RAG / 知识问答：** 检索结果只作为候选知识，再结合门店范围、知识状态、版本和问题歧义决定回答、拒答或转人工；避免“检索到内容”直接等同于“可以回答”，并通过无答案 / 歧义等 Case 检查知识边界。

- **权限 / 业务状态：** Agent 可以识别用户意图并提出业务动作，但身份、门店范围、权限和最终写操作由服务端控制；Ticket / 人工接管等动作需经过权限检查、状态写入、持久化及按权限范围回读验证后才视为完成。

- **系统集成：** 完成 **React、Node.js、PostgreSQL、Docker 与内部 FastAPI / pgvector 服务**集成，验证数据库迁移、服务重启后状态保持、权限隔离及核心业务流程，使 Agent 能够进入实际业务状态而非停留在单轮问答 Demo。

- **评测 / 验收：** 建立 **40-case Frozen Set + 60-case Blind Holdout**，覆盖正常回答、无答案 / 歧义、Negative Case、Tool Use、权限及业务状态等关键场景；结合 Bad Case、Regression、Eval Harness、CI / Quality Gate 进行版本回归，并将知识问答、业务动作、人工接管和系统集成拆开验收，判断修改是否造成其他链路退化。
