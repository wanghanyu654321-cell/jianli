淘天 Data Agent 正式经历进一步强化了业务规则理解、需求澄清、上下游沟通和质量闭环能力：能够把抽象业务要求转化为下游可执行的标准、案例和培训内容，并通过 QA、Bad Case 和版本效果观察持续发现需求缺口和执行问题。

此前两段电商经历证明了复杂业务中的交付和项目推进能力：在朗臻从单品运营逐步承担项目运营管理，负责约 **5 个跨平台店铺**，年度整体 GMV 约 **1,500 万**；在今宜参与抖音新盘 0→1，同一账号月 GMV 从早期约 **7 万提升至接手首月约 43 万**。能够在业务目标、资源、成本、进度和结果之间做优先级判断并推动多角色落地。

## 工作经历

### 杭州人瑞网络科技有限公司｜评测专家（淘天 Data Agent）｜2025.09–2026.06

- **需求分析：** 承接上游业务文档、数据口径和任务要求后，结合实际 Case 理解规则适用范围、业务上下文和执行难点，再完成必要对齐。
- **需求澄清：** 新任务放量前主动识别定义不清、场景覆盖不足、上下文缺失或判断空间过宽等问题，并集中反馈上级确认，避免问题在大规模执行后才暴露。
- **标准转译：** 将上游业务要求转化为 BPO 可执行的判断标准、案例和培训内容，累计参与沉淀 **10+ 份 SOP / 规则 / 执行文档**。
- **问题定位：** 对复杂 Bad Case 区分业务知识、规则边界、上下文和执行流程问题，再推动说明、示例、培训或执行方式调整。
- **项目推进 / QA：** 在上级和 BPO 团队之间持续同步阶段、问题和待确认事项；单项任务下游 BPO **10+ 人**，部分任务一致性约 **80%→95%**、复杂任务约 **60%→85%**。
- **版本验证：** 参与灰度 / A/B 及数据取数，结合 DAU、CTR、转化和业务水位观察版本效果和异常反馈。

### 杭州今宜商贸有限公司｜抖音项目代运营｜2024.11–2025.07

- **目标拆解：** 项目启动阶段先与老板确认当前更偏 GMV、ROI、利润还是新盘增长，再据此确定内容、投流、达人合作和资源投入优先级。
- **方案优先级：** 起盘初期发现素材、直播环境、机位和主播承接仍有明显问题，因此先补内容与直播转化能力，再逐步扩大付费流量，避免用预算掩盖底层问题。
- **内容方案：** 围绕目标用户和核心卖点设计短视频 / 直播表达，先通过短视频数据验证，再将有效方向迁移到直播并参与双机位方案设计。
- **千川投流：** 本人直接使用巨量千川，根据 CTR、CVR、ROI、素材和直播承接定位问题层级，并通过不同素材、主播或执行方案对比持续验证。
- **项目推进：** 协同约 **6 人直播团队**推进目标、排期、主播、内容、投流和复盘；同一新盘账号月 GMV 从早期约 **7 万提升至接手首月约 43 万**。
- **达人 BD：** 参与达人筛选、触达和合作推进，相关达人合作单月销售额合计 **10 万元+**。

## 项目经历

### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**项目背景：** 面向门店微信等私域入口，解决重复咨询响应不及时、预约 / 线索意向容易丢失、异常问题缺乏稳定转人工流程等问题。

**本人负责：** 问题定义、需求拆解、方案边界、验收标准、评测设计、方案取舍、测试验收和项目状态判断。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL / pgvector｜Docker Compose｜Agent｜RAG｜Tool Use｜Eval / Regression / CI

- **需求分析：** 第一阶段优先解决常见咨询、预约 / 线索和异常转人工，不重建完整 CRM，也不扩展为全能数字员工。
- **方案设计：** 将线上第一接待拆成知识问答、轻量业务状态、权限控制、Ticket / 人工接管等模块，并将渠道 / 身份适配与 Agent 运行时解耦。
- **RAG / 知识问答：** 检索只产生候选知识，再结合门店范围、知识状态、版本和歧义情况决定回答、拒答或转人工。
- **权限 / 业务状态：** 模型负责理解意图并提出动作，最终业务权限由服务端控制；写操作需完成权限检查、持久化和 scoped read-back 后才视为成功。
- **系统集成：** 完成 React、Node、PostgreSQL、Docker 与内部 FastAPI / pgvector 服务集成，验证数据库迁移、重启后状态保持、权限隔离和核心业务流程。
- **POC 交付：** 已完成微信部署与实体本地生活门店 POC，门店开始在接待场景中使用，项目从内部工程验证进入门店流程验证。
- **验收 / 回归：** 将正常回答、无答案 / 歧义、权限、真实业务动作、人工接管和系统集成分开验收，并通过评测集、回归测试和门店 Case 持续迭代。
