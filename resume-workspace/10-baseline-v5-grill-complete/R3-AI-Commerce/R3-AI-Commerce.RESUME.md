### 数字前台 Agent｜门店微信接待 / 知识问答 / 预约线索 / 人工接管

**项目属性：** 个人 Agent 项目。

**项目背景：** 面向实体本地生活门店微信等私域入口，解决重复咨询响应不及时、预约 / 服务意向容易丢失、异常问题缺少稳定人工接管的问题。

**本人负责：** 问题定义、需求拆解、方案边界、验收标准、评测设计、Bad Case 归因、方案取舍、测试验收和项目状态判断；通过 AI Coding Agent 协作完成实现与 Review。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL 16 / pgvector｜Docker Compose｜Agent｜RAG / 知识库｜Tool Use｜Eval / Regression / CI

- **微信部署 / 门店 POC：** 已完成**微信部署与实体本地生活门店 POC**并开始进入实际接待场景使用；现场咨询、异常、人工接管和一线反馈持续进入后续评测与版本迭代。

- **Query / 用户意图：** 将过去 Search / Query、商品语义和用户需求判断迁移到 Agent 意图识别与知识问答场景，重点判断用户真正想解决的问题，并区分字面 Query、知识需求及后续业务动作。

- **RAG / 检索质量：** 检索结果只作为候选知识，再结合门店范围、知识状态、版本和歧义决定回答、拒答或转人工，使“召回到内容”和“内容当前可被业务使用”保持区分；通过无答案、歧义和 Negative Case 持续验证知识与检索边界。

- **业务链路设计：** 围绕 **咨询 → 预约 / 服务意向 → 轻量业务状态 → Ticket / 人工接管 → 人工跟进**形成最小可运行链路，使用户意图能够继续进入后续业务流程，而不是停留在单轮问答。

- **Agent评测 / 质量闭环：** 将质量判断从最终答案扩展到知识依据、无答案 / 歧义、Tool Use、权限、业务状态和执行轨迹；建立 **40-case Frozen Set + 60-case Blind Holdout**，并将实际 Query、异常及人工接管 Case 回流 Dataset / Regression Set，持续检查版本修改是否破坏已有行为。

- **Tool Use / 权限控制：** Agent 可以识别意图并提出动作，但最终权限和业务写操作由服务端控制；业务动作需完成权限检查、状态写入、持久化和按权限范围回读后再验收，避免把模型输出直接视为业务成功。
