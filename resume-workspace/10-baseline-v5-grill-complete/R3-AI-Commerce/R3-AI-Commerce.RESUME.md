## 工作经历

### 杭州人瑞网络科技有限公司｜Data Agent 评测｜2025.09–2026.06

- **电商 Query / 相关性：** 参与淘天 Data Agent 的 Query、召回结果、商品相关性和 Agent 输出评测，将用户搜索意图、商品语义及业务规则落实到具体案例判断。
- **搜索链路理解：** 接触 Query Understanding / Rewrite、召回、Filter、排序、SERP 和反馈链路，并使用 L1/L2/L3 判断商品与需求的匹配程度。
- **复杂 Bad Case 与业务上下文：** 对判断分歧区分业务上下文、规则边界和执行理解等问题，再推动判断口径持续收敛。
- **质量规模与结果：** 单项任务下游 BPO **10+ 人、每周约 5,000–10,000 条**；部分任务一致性约 **80%→95%**，复杂任务约 **60%→85%**。
- **版本与业务指标观察：** 参与执行层灰度 / A/B 和数据取数，结合 DAU、CTR、转化、业务水位观察版本效果。

### 杭州今宜商贸有限公司｜抖音项目代运营｜2024.11–2025.07

- **新盘 0→1：** 进入新盘后先从产品、内容、直播承接和流量链路判断关键问题，而不是直接增加预算；同一账号月 GMV 从早期约 **7 万提升至接手首月约 43 万**。
- **产品定位：** 根据健身轻食需求增长，将玉米包从常见宝宝辅食表达调整到健身轻食 / 营养健康场景，并重新组织核心卖点和使用情境。
- **短视频到直播验证：** 先用短视频素材测试不同卖点、画面和场景，观察哪类表达更容易获得点击和后续转化，再将有效方向迁移到直播，并参与双机位方案设计。
- **投流与漏斗诊断：** 本人直接使用巨量千川，根据 CTR、CVR、ROI、素材和直播承接判断问题位于内容、流量匹配还是后端转化；例如 CTR 高但 CVR 低时继续检查流量质量、产品表达、价格和直播话术，而不把高点击直接判断为成功。
- **对比实验与归因：** 多个变量同时变化时尽量统一数据口径及其他关键条件，通过素材、主播或执行方案对比缩小问题范围。
- **达人冷启动：** 新盘缺乏历史销量、权重和成熟素材时直接开发达人，以内容匹配、粉丝 / 历史销售和合作意愿筛选优先级；达人合作 **单月销售额合计 10 万+**。
- **团队协作：** 协同约 **6 人直播团队**推进策略、排期、内容、主播、投流和复盘；GMV 为项目整体结果，不将团队结果包装成个人单点贡献。

## 项目经历

### 数字前台 Agent｜商家 / 服务 Agent 场景实践

很多实体商家通过微信等渠道已经拥有私域流量，但“获得流量”并不等于“流量被有效承接”。数字前台项目因此把线上第一接待、知识库、预约 / 线索意向和人工接管串成一条最小业务链，并已完成微信真实部署与实体本地生活门店 POC，门店开始在真实接待场景中使用。

**技术栈：** TypeScript / Node.js｜React｜Python / FastAPI｜PostgreSQL 16 / pgvector｜Docker Compose｜RAG / 知识库｜Prompt / 指令｜工具调用｜Agent 运行时｜评测 / 回归测试 / 测试框架

- **私域流量承接：** 从电商经营视角进一步验证，流量进入私域后仍需要第一接待、需求识别和后续承接，否则用户价值并没有真正进入业务流程；微信真实部署后，这一链路开始进入真实门店场景，而不再只是产品假设。
- **Query / 知识能力迁移：** 将过去 Search / Query Intent、商品语义和用户需求判断进一步迁移到 Agent 意图识别、知识库和证据判断，使原有电商判断能力能够进入真实商家 / 服务 Agent 场景。
- **POC 验证：** 已完成实体本地生活门店 POC，门店开始使用数字前台承接线上咨询与后续意向；AI 带来的 GMV、转化率或客服效率提升仍待数据验证。
- **智能服务应用：** 当前项目补充商家 / 服务 Agent、业务流程、权限、真实业务状态和评测等 AI 应用场景；R3 的核心定位仍是“完整电商经营能力 + 已进入真实商家 Agent 场景”，个人 Agent 项目用于补强 AI 场景证据，不替代正式经营经历。

**项目状态：** 已完成微信部署与实体本地生活门店 POC，门店开始实际使用；AI 电商侧的长期使用、规模化复制与业务增量指标仍待持续验证。
